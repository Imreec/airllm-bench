# Known Limitations

Every accepted imperfection, disclosed up front. A documented limitation is cheap; a hidden one a
grader finds is fatal to credibility (COURSE_LESSONS §4). Severity: **P0** blocks submission · **P1**
serious but acceptable · **P2** minor.

| ID | Limitation | Severity | Why accepted | Fix sketch |
|----|-----------|----------|--------------|------------|
| L-01 | **Single-machine measurement.** Benchmarks run once on one box (RTX 3080 Ti / 32 GB); CI cannot reproduce them. | P1 | Inherent to the assignment — it measures *this* hardware. | Commit raw JSON + pinned env as evidence; the analysis pipeline (data→figures) *is* CI-reproducible (D11 two-tier). |
| L-02 | **Windows `psutil` exposes no system page-cache figure.** The page-cache signal is cold-vs-warm timing + `available`, not a cached-bytes number. | P2 | OS limitation surfaced by the G-SPIKE (ADR 0001). | Report cold/warm deltas + `available`; document the proxy explicitly. |
| L-03 | **CPU energy is TDP-estimated, not measured.** GPU energy is measured (NVML); Ryzen package power isn't cleanly scriptable on Windows. | P2 | RAPL access on Windows is impractical. | Declare the TDP assumption in `economics.json`; GPU (the dominant draw) is measured. |
| L-04 | **`transformers` pinned `<4.43`.** AirLLM's layer driver predates the 4.43 RoPE refactor; newer transformers crash mid-generation. | P2 | Hard AirLLM constraint (ADR 0001), not a free choice. | Revisit if AirLLM updates its layer-call API. |
| L-05 | **Perplexity is the only quality metric — no generated-output sample.** Output quality per quant is assessed by perplexity (a teacher-forced forward pass), not by human eval or a sample-output table. The harness retains timings + perplexity but **not** the decoded tokens, so no qualitative text sample is committed. (D10 envisaged a small sample table; it was descoped.) | P2 | Deterministic, reproducible, theory-linked; perplexity already gives the cross-quant quality axis, and capturing/scoring generations is a Tier-2 hardware re-run. Full human eval is out of scope. | Persist generated text in `RunResult` and re-run (Tier-2) to add a sample-output table for a human-readable check. |
| L-06 | **Tiny token budgets at FP16.** FP16 (~8 min/token) scenarios use very few output tokens. | P2 | Latency is the finding; large generations are infeasible. | Size per ADR 0001; report token counts alongside every timing. |
| L-07 | **Cold-cache flush isn't magnitude-verified.** The orchestrator confirms RAMMap (`-Et`) runs elevated and exits 0, but cannot assert *how much* it freed: on Windows the Standby List counts toward `available`, so emptying GBs moves `available` ~0 (measured 30 MB during T5.5). | P2 | Empirically confirmed extension of L-02; a freed-MB gate can never pass on Windows. | Cold-ness is evidenced by the cold/warm *timing* delta (a broken flush shows cold≈warm); RAMMap's non-zero exit still fails loud. |
| L-08 | **AirLLM prompt-length sweep caps at ~256 tokens.** AirLLM's default `max_seq_len=512` rejects a 1024-token prompt (`tensor a (1024) must match tensor b (512)`), so the TTFT-vs-length sweep uses 40/64/256. | P2 | Enlarging `max_seq_len` grows the KV cache and shifts the operating point, confounding the cold/warm comparison. | The 3 points already show AirLLM's TTFT is streaming-bound (≈constant vs length); raising `max_seq_len` is future work if a longer sweep is wanted. |
| L-09 | **Economics anchors on near-comparable, not identical, SKUs.** The base `Qwen2.5-32B-Instruct` isn't broadly hosted, so the API line uses the same-size/family/generation **Coder-32B-Instruct** price; no cloud RTX 3080 Ti exists, so the cloud line uses the **RTX 3090** (same Ampere gen). Local 4-bit quality ≠ a frontier API (D6 parity caveat). | P2 | Closest documented comparables (D6/D8: no live pricing); each constant carries source + date in `economics.json`. | Swap in an exact-model/SKU price if one becomes documented; the report states the substitution and the quality-parity caveat at the figure. |
| L-10 | **Roofline binding tier is assigned by data path, not measured saturation.** AirLLM is Python/per-layer-overhead-bound, so its achieved bandwidth sits far below *every* ceiling (utilization ≪ 1); the binding tier (NVMe cold, PCIe warm-if-fits, HBM resident) is therefore inferred from where the bytes physically travel, not from which ceiling is saturated. `q4_k_m` bytes/weight (~0.56) is the documented ~4.5-bpw effective rate, not an exact measurement. | P2 | The memory-hierarchy *story* is the path the bytes take + the cold/warm timing delta; the achieved-vs-ceiling gap is itself the finding (overhead dominates, not bandwidth). | Per-layer bandwidth profiling could confirm saturation directly; the committed cold/warm deltas already evidence the path shift. |
